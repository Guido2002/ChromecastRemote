# Chromecast Remote v0.12.0

Android version **0.12.0**, build **14**.

## Voice search

Hold the microphone on a compatible Android TV remote, wait for Listening, and speak directly to the TV. Release to end the request; recording stops automatically after ten seconds. The app checks microphone permission and waits for a TV-reported voice session before capturing audio. Unsupported connections keep voice search disabled.

Leaving Remote, changing targets, losing the connection or backgrounding the app cancels capture and discards unsent audio. Audio is not saved or transcribed on the phone. The TV's voice service may process it online. A sent request does not confirm recognition or execution.

## Smart Now Playing

The Remote pane automatically switches to a dedicated media view for a connected Cast session with matching receiver/media identity. It shows reported artwork, title, progress, playback controls and receiver volume. Pause and seeking follow receiver capabilities.

Choose TV remote to return to navigation without stopping playback. The choice persists for that media session. Ending the session restores the normal remote; Apps and Devices keep their navigation context. Ordinary Android TV apps continue to show only reported state and available key commands.

## Haptic feedback

Settings now includes a saved Haptic feedback switch. Remote actions produce consistent local feedback, held controls pulse once, and duplicate playback feedback has been removed. Tooltip holds do not bypass the preference. Feedback represents a local press, not a TV acknowledgement.

## Layout and reliability

Playback controls wrap on narrow screens. Cast headers and volume labels accommodate enlarged text. Native capability reads have a timeout, and stale receiver/media responses cannot activate the wrong controls.

## Compatibility boundaries

Voice search and Cast behavior still require physical-TV testing across assistants, apps and receivers. Automated tests and fixture-based visual checks do not establish universal compatibility. Keyboard input remains a preview. Audio already sent cannot be recalled.

No iOS binary is released. The source project includes a microphone usage declaration, but Xcode is unavailable here, so iOS compilation, signing and runtime verification remain outstanding.
